# ADR 0001：加入「重生」模式，培养应用型历史思维

- 状态：提议（未实施）
- 日期：2026-10-14
- 决策人：项目作者
- 涉及：`js/engine/`（新增通用能力）、`js/story/<id>.js`（剧本格式扩展）、`tools/playtest.js`

---

## 1. 背景

现有模板是「正史线」游戏：沿着史实走完剧情，收集史料卡，读章末小结。它能让孩子**知道**一段历史，但不能检验孩子会不会**用**历史的方法想问题。

新想法：通关正史线后，解锁「重生」模式。孩子回到关键时刻，在当时的条件下重新做决定，不同的选择和资源会带来不同的结局。重生的分支先预设好，以后可以接入大模型。

### 1.1 JTBD 分析：谁在「雇用」这个游戏

**雇用者是家长**（已定）。玩的人是孩子，掏钱、挑选、判断值不值的人是家长。

| 角色 | 功能任务 | 情感任务 | 社会任务 |
|---|---|---|---|
| 家长（雇用者） | 让孩子学会用历史的方法想问题，而不是只背年代 | 放心：孩子在学，不是在瞎玩；史实不会被教歪 | 能看到孩子思考的成果，能和孩子聊、能拿给别人看 |
| 孩子（玩家） | 搞懂这段历史讲了什么 | 「我能改变结局」的掌控感；满足「如果当时……」的好奇心 | 能和别人讲「我推出了不一样的结局」 |
| 模板作者 | 换一段历史就能快速做出同类游戏 | — | — |

**核心任务：**
> 当孩子学完一段历史后，我（家长）想让他站在当时人的位置、用当时的条件重新做一次决定，从而理解这件事为什么会这样发生——并且我能看到、能和他聊他是怎么想的。

### 1.2 「应用型历史思维」练什么

参照 Seixas 的六个历史思维概念：

| 概念 | 正史线 | 重生线 |
|---|---|---|
| 证据 | ✅ 史料卡已区分「史实/演绎」 | 每个选择都要引用史料卡作为依据 |
| 因果 | 部分 | ✅ 主战场：改变一个原因，看结果怎么变 |
| 历史视角 | 部分 | ✅ 主战场：只能用当时的信息和资源 |
| 延续与变迁 | 章末小结 | 不同结局的长远影响 |
| 历史意义 | 章末小结 | 对比：正史结局为什么重要 |
| 伦理维度 | — | 可选：选择的代价由谁承担 |

### 1.3 竞争方案（家长现在会「雇」什么）

| 现有方案 | 完成了什么 | 没完成什么 |
|---|---|---|
| 课本加背诵 | 知识点 | 缺少因果和视角 |
| 历史故事音频、动画 | 情节好记 | 孩子只是被动接收 |
| 《文明》类策略游戏 | 决策和资源 | 不讲具体史实，对小学生太复杂 |
| 穿越小说、短视频 | 「如果」的乐趣 | 用现代知识开挂，反而破坏历史思维 |
| 亲子共读后聊天 | 最接近目标 | 家长不一定知道该问什么 |

本游戏的定位是：给家长一份**能聊的材料**（推演报告），替家长把该问的问题问出来。

## 2. 决策

### D1 先正史，后重生
正史线通关后才解锁重生。正史线负责建立证据基础，重生线负责应用。没有证据基础的「如果」只是瞎猜。

### D2 重生没有胜负感，产出物是推演报告（已定）
- 不设星级、排名或「最佳结局」。结局之间没有好坏之分，只有「和正史有什么不同、为什么不同」。
- 每次重生结束，生成一份**推演报告**，内容包括：
  1. 我在哪几个关键时刻改了什么
  2. 每次选择依据的是哪张史料卡
  3. 结局是什么，属于「史实 / 合理推演 / 历史上没有发生」中的哪一种
  4. 和正史对比：为什么会走到这一步
- 报告是**拿来分享的**：孩子可以保存多份报告并排对比，也可以拿给家长看、讲给家长听。

**为什么不要胜负感：** 一旦有「最好结局」，孩子的目标就会变成刷结局，自然会用后见之明开挂，这恰恰和历史思维背道而驰。

### D3 约束「后见之明」
- **信息约束**：重生时，孩子只知道当时的人能知道的事。正史里的剧透不能直接变成选项，必须在游戏里通过打听、侦察，用资源去换。
- **资源约束**：资源要贴合时代（以张骞为例：人手、马匹粮草、礼物财物、汉朝的名义、向导）。每个选择都要消耗资源，不能什么都要。
- **结局要有依据**：每个结局都标注依据类型，沿用史料卡的标注习惯。所有分支都要走 `history-fact-checker` 核查。

### D4 预设分支先行，为大模型留接口
- v1 全部用预设：可核查、可离线、能打包成单文件，也没有儿童隐私问题。
- 数据结构里预留「选择 + 理由」槽位。v1 让孩子从 2～3 个预设理由中挑一个。
- 以后接入大模型时，它的职责是**评判孩子的理由**（用了哪些证据、有没有后见之明），**不负责生成剧情和史实**。结局仍然用核查过的预设版本。

### D5 用《张骞传》做最小验证
不新开题材，在现有剧本上加重生线。候选决策点如下（**史实待核查**）：
- 被匈奴扣留十余年期间：逃不逃、什么时候逃、带不带家人
- 到了大月氏，对方不愿报仇：怎么劝、用什么资源，还是转去收集情报
- 归途选哪条路（史载想经羌中回去，结果又被匈奴抓住）

规模控制在：3 个决策点、4～5 种资源、约 4 个结局。

**验证标准：** 孩子玩完重生，能不能用自己的话说出「张骞没能说服大月氏，是因为……」。

## 3. 像素 RPG 的场景和画面撑不撑得住

### 3.1 现状盘点（2026-10-14）

| 项目 | 现状 |
|---|---|
| 美术来源 | 全部用代码绘制，没有美术素材文件（史料卡照片除外） |
| 人物 | 16×16 通用模板，靠换颜色加配件（胡帽、胡子、冠、节杖……）区分。引擎自带 18 种，张骞剧本另加 18 种 |
| 建筑和地标 | `buildings.js` 中共 26 种（宫殿、毡帐、烽燧、绿洲城、关隘……） |
| 地形主题 | 城镇 8 种（城市、村庄、沙漠、雪地、海岸、草原……），迷宫 9 种 |
| 地图生成 | 世界地图由剧本里的粗格字符画生成；城镇由「槽位 + 建筑类型」的数据表生成 |
| 体积 | `dist/张骞传.html` 1.5 MB，大头是史料卡图片；代码约 3000 行 |

### 3.2 结论：撑得住，但有条件

**重生线不会让场景数量成倍增长。** 同一段历史的地理是固定的，重生改变的是**状态**，不是**地图**：同一座匈奴营地，换一个选择后，NPC 说的话、谁在场、哪里能去都会变。现有引擎已经通过 flag 和 `cond` 做到这一点。新场景只在少数结局需要（例如「留在大月氏」）。

**真正要新增的是三种「非地图画面」，它们本质上是 UI：**
1. **抉择画面**：一个关键时刻、几个选项、每个选项的资源消耗和依据卡
2. **资源面板**：常驻的小面板，显示当前资源
3. **推演报告页**：可以翻看、可以对比、可以导出

像素风的文本框和菜单（`core.js` 的 `Menu`）足够撑起这些画面，不需要新的美术风格。

### 3.3 撑不住的地方

| 场景类型 | 问题 | 对策 |
|---|---|---|
| 大场面（战役、朝会、万人迁徙） | 16×16 小人摆不出规模感 | 用旁白加史料卡（文物、古画照片）代替画面；或者改用小人物视角 |
| 表情和情绪特写 | 小人只有几个像素，没有表情 | 对话框加人物头像（需要新做，成本中等） |
| 抽象过程（变法、制度、经济） | 「走路 + 说话」的玩法表达不出来 | 不适合用作主线；要做的话需要新的玩法类型 |
| 海上题材（郑和、鉴真） | 没有船和海上航行 | 在 `scene-art` 里补，属于一次性成本 |

### 3.4 对选题的影响
最适合的历史事件是：**人物在地理空间中移动，并且一路要做决定**，比如出使、远行、迁徙、求学、逃亡、取经。以战役或制度为核心的事件，要么换成小人物视角，要么暂时不做。

### 3.5 真正的瓶颈不在画面，在内容和测试
- **分支爆炸**：3 个决策点、每个 3 个选项，就有 27 条路径。设计上要求路径**收敛**到约 4 个结局；`playtest.js` 必须能遍历所有路径。
- **史实核查量**：每个结局和每条依据都要核查，工作量大约是正史线的 1.5～2 倍。
- **单个新造型**：走 `scene-art` 流程，每种约需一轮画廊确认。

## 4. 后果

**得到的：**
- 游戏从「知道历史」升级到「会用历史想问题」，家长能拿到看得见、能聊的成果
- 引擎新增的资源、抉择、多结局、报告都是通用能力，换题材时可以复用

**付出的：**
- 引擎要新增 4 块通用能力，剧本格式要扩展，`engine-check` 必须继续通过
- 每个题材的内容和核查工作量大约翻倍
- 没有胜负感，对部分孩子的吸引力会弱一些；要靠「推出别人没推出的结局」和分享报告来补

**反悔成本：**
- 重生模式是正史线之后的附加层。如果放弃，删掉入口即可，正史线不受影响，**成本低**
- 如果以后想加胜负感，加起来容易，但会改变报告的性质；**先加再撤则很难**，所以 v1 不加

## 6. 考虑过但没有采用的方案

| 方案 | 不采用的原因 |
|---|---|
| 重生设星级或排名 | 会诱导孩子刷结局、开挂，违背目标（见 D2） |
| v1 就接大模型生成剧情 | 史实不可核查，需要联网，有儿童隐私问题，也打不成单文件 |
| 一开始就开放重生，不要求先通关正史 | 没有证据基础，「如果」只是瞎猜 |
| 新开题材来验证 | 张骞已有完整的正史线和史料卡，在它上面验证成本最低 |
